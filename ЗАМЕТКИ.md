# Заметки к решению

## Очередь

Берём первую заявку, которой хватает мест. Большая может ждать. Недействующую (не хватает посещений или истёк срок) снимаем сразу, даже если мест ещё нет: при выходе ответ `cancelled`, в базе остаётся `skipped`.

Запись и увеличение мест сначала догоняют чужую очередь, свою заявку не трогают. Отказ откатывает это продвижение. Отмена и уменьшение мест свою заявку снимают до продвижения, иначе клиент сразу получил бы вторую бронь. На занятии, которое отменил клуб, очередь не двигается.

Если мест хватает, ответ `seats-available`, даже когда в очереди ещё кто-то стоит.

## Свои причины `409`

| `reason` | Когда |
|---|---|
| `idempotency-mismatch` | тот же ключ, другое тело |
| `already-promoted` | из заявки уже создана бронь; в ответе есть `promotedEnrollmentId` |
| `exceeds-capacity` | в очереди запрошено больше вместимости. Свободных мест может ещё не быть, это другой отказ, чем `capacity-exceeded` |

## Идемпотентность

`404` и `409` под ключом не запоминаются, тот же ключ можно отправить снова. Повтор успешной постановки возвращает `position` из первого ответа.

## Время, кэш, лимит

- Время записи усекается до микросекунды, иначе одна и та же бронь отдаёт разное `createdAt` после чтения из Postgres.
- Карточка читается только из Redis: локальная копия между экземплярами не сбрасывается. Сброс идёт после коммита, сбой Redis его не отменяет.
- При недоступном Redis лимитер отвечает ошибкой и запрос не пропускает.

## Расписание

Токен продолжения — позиция страницы: время начала и id занятия, без подписи и без привязки к фильтрам. Клиент может собрать его сам. Дата без времени означает полночь UTC.
